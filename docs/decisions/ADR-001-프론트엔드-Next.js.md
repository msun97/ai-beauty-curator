# ADR-001. 프론트엔드 프레임워크: Next.js (App Router)

- 날짜: 2026-11-16
- 상태: 채택

## 문제 및 배경
React + TypeScript로 모바일 퍼스트 웹(PWA)을 만든다. 서비스 특성상 상품 상세 링크가 메신저·SNS로 공유되며(FR-SHR-02), 공유 시 상품 이미지와 이름이 미리보기로 보여야 한다.

## 검토한 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| Vite + React (SPA) | 구조가 단순하고 빌드가 빠름 | 페이지별 메타 태그(OG)가 클라이언트에서 그려져 공유 미리보기 처리가 어려움 |
| **Next.js (App Router)** | 서버 렌더링과 페이지별 메타데이터 생성 지원, Vercel 배포가 간편 | 서버·클라이언트 컴포넌트 구분 등 학습할 개념이 많음 |

## 선택한 방안
Next.js (App Router) + TypeScript + Tailwind CSS

## 선택 이유
- 상품 상세 페이지의 공유 미리보기(OG 태그)를 서버에서 생성할 수 있다.
- 트렌드 피드처럼 첫 화면 로딩이 중요한 페이지를 서버에서 렌더링해 초기 로딩 목표(NFR-PERF-03)에 유리하다.
- Tailwind CSS는 Figma 화면 설계의 디자인 토큰(색, 간격)을 그대로 옮기기 쉽다.

## 영향
- 비즈니스 로직과 데이터는 Spring Boot API가 담당하고, Next.js는 화면 렌더링만 담당한다.
- Next.js 서버 컴포넌트에서 백엔드 API를 호출할 때는 서버 전용 환경 변수(`API_BASE_URL`)를 사용한다.

## 재검토 조건
- 공유 미리보기 요구사항이 사라지거나, 서버 렌더링 비용이 운영에 부담이 될 때
