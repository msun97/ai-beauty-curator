# ADR-003. 데이터베이스 실행·배포 방식: 로컬 Docker + 운영 Neon

- 날짜: 2026-11-16
- 상태: 채택 (운영 DB는 배포 단계에서 계정 생성)

## 문제 및 배경
DB는 PostgreSQL을 사용한다. 1인 개발이므로 운영 부담 없이 배포하기 쉬운 방식이 필요하고, 로컬 개발 환경은 누구나 같은 방식으로 재현할 수 있어야 한다.

## 검토한 대안 (운영 DB)
| 대안 | 장점 | 단점 |
|---|---|---|
| **Neon** | 관리형 서버리스 PostgreSQL, 무료 플랜, 연결 문자열만으로 사용, 브랜치 기능 | 무료 플랜은 미사용 시 일시 정지되어 첫 요청이 느릴 수 있음 |
| Supabase | PostgreSQL + 인증·스토리지 등 부가 기능 | 부가 기능은 Spring Boot에서 직접 구현하므로 활용도가 낮음 |
| Railway / Render DB | 백엔드와 같은 곳에서 관리 | 무료 사용 범위가 제한적이거나 기간 제한이 있음 |
| 직접 운영(EC2 등) | 자유도가 높음 | 백업·보안 패치 등 운영 부담이 큼 |

## 선택한 방안
- **로컬:** Docker Compose로 PostgreSQL 17 실행 (포트 5433)
- **운영:** Neon (PostgreSQL 17)

## 선택 이유
- 로컬과 운영 모두 PostgreSQL 17을 사용해 버전 차이로 인한 문제를 줄인다.
- Neon은 환경 변수(`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`)만 바꾸면 연결되므로, 애플리케이션 코드 변경 없이 배포할 수 있다.
- 로컬에 이미 설치된 PostgreSQL(5432)과 충돌하지 않도록 Docker 컨테이너는 5433 포트를 사용한다.

## 배포 구성 (예정)
| 구성 요소 | 배포처 | 비고 |
|---|---|---|
| 프론트엔드 (Next.js) | Vercel | Next.js 공식 배포 환경 |
| 백엔드 (Spring Boot) | Render 또는 Railway | `backend/Dockerfile`로 컨테이너 배포 |
| 데이터베이스 | Neon | 연결 시 `sslmode=require` 사용 |

## 재검토 조건
- 무료 플랜의 일시 정지로 응답 지연(NFR-PERF-01)이 문제가 될 때
- 트래픽이나 데이터 용량이 무료 범위를 넘을 때
